## 불확실 영역을 반영할 평가 설계와 다음 승인

1. **버전 승인.** 사용자가 이미지별 버전·박스 번호를 지정해 D20과 D40을 승인하거나 보류합니다. 120번의 2번은 포트홀 추가 승인 대상이고, 3·4번은 저장 클래스와 메모 중 최종 의도를 확인해야 합니다. 135번의 전체 제외와 배경 후보 판정도 별도로 확인합니다. 버전을 다시 저장하면 메모와 좌표를 새로 검토합니다.
2. **평가 범위.** 전체 보류 이미지는 예측·정답 양쪽의 집계에서 먼저 제외합니다. 프레임 전체를 확인하지 않았거나 보류 구역에 좌표가 없는 프레임은 포괄적인 Precision·FP 집계에서 보류합니다. 불확실 영역은 별도 목록으로 유지하고 승인 GT나 정상 배경 수에 넣지 않습니다.
3. **부분 보류 영역.** 기존 `_read_truth()`는 YOLO 클래스와 박스만 읽고, `match_boxes()`와 오류 집계에는 제외 이미지·불확실 영역 입력이 없습니다. 개선 시 승인 GT를 먼저 일대일 매칭하고, 남은 예측 중 불확실 영역에 걸친 예측은 별도 검토합니다. 사전 합의할 예시 규칙은 ‘불확실 영역 합집합과의 교집합 / 예측 면적 ≥ 0.5이면 평가 보류’입니다. 작은 예측이 큰 보류 영역에 들어가도 반영되는 기준입니다. 이미 매칭된 정답 주변의 중복 예측과 클래스 혼동이 이 규칙에 의해 가려지지 않는지 별도 테스트합니다. 적용할 임계값·무시 건수·집계 가능한 이미지 수를 기록합니다. [기존 매칭](../../src/road_anomaly/yolo_evaluation.py) · [기존 오류 분류](../../src/road_anomaly/yolo_error_analysis.py)
4. **Part 5.3-3 진입 조건.** 보류와 제외 처리를 시험한 뒤, 승인된 버전만 별도 평가용 GT로 발행합니다. 동일 파손 추정 그룹을 유지하고 프레임별 결과와 사례별 결과를 구분합니다. 현재 실제 영상의 Recall·Precision·FP는 미측정이며 서비스 적용도 보류 상태입니다.

### 배경 8장 검토 방법

프로젝트 루트에서 기존 편집기의 배경 세션을 엽니다. 이미지 8장은 모두 v0000, 미검토, 박스 0개로 준비했습니다. 새 버전과 메모는 별도 경로에 저장됩니다. [배경 검토 세션](../../data/processed/dashcam_validation/part532_candidate_review/background_drafts)

```powershell
.\.venv\Scripts\python.exe -B -X utf8 scripts\annotate_dashcam_drafts.py edit --background
```

1. 전방 4장과 후방 4장을 차례로 엽니다. 원본 전체를 보고 필요하면 ‘노면 확대’와 ‘ROI B 표시’를 사용합니다. ROI 밖의 노면도 검토합니다.
2. 보이는 범위에서 평가 대상 파손이 없다고 직접 판단한 경우에만 **파손 없음**을 선택합니다. 명확한 후보는 드래그하고 클래스 선택 → **박스 적용** → **초안 작성** 순서로 기록합니다. 작업 도중에는 **검토 중**을 선택할 수 있습니다.
3. 불확실한 위치를 특정할 수 있으면 **판단 보류** 클래스로 박스를 그립니다. 이미지 전체를 판독하기 어려우면 박스 없이 이미지 상태를 **판단 보류**로 두고 제외 사유를 적습니다. **초안 저장** 후 다음 장으로 이동합니다. 파손 없음과 박스가 함께 있으면 저장을 거부합니다.

Windows 편집기에서 실제 배경 프레임 8장을 모두 열어 원본 해시와 초기 상태를 확인했습니다. 신규 회귀 테스트 2개를 포함한 관련 테스트 24개와 전체 96개가 통과했습니다. 원본 MP4·프레임, 기존 검토 자료, 사용자 저장 버전, 이전 승인 자료를 포함한 159개 파일의 작업 전후 SHA-256도 일치했습니다.

### Part 5.3-3 평가 설계

아래는 v2 당시 제안입니다. 3항의 일괄 FP 처리는 v3에서 라벨 완전성을 고려해 수정했습니다. 기존 오류 집계에는 이미지 제외 목록과 보류 영역 입력이 없습니다. [현재 평가 기준](../experiments/part5_dashcam_manual_box_drafts.md#part-53-3-진단용-평가-기준) · [기존 매칭 코드](../../src/road_anomaly/yolo_evaluation.py)

1. **표본 선택.** 사용자가 지정한 이미지·버전·박스만 평가에 사용합니다. 전체 보류·미검토·검토 중인 프레임은 예측과 정답 양쪽에서 제외합니다. 빈 GT 배경은 사람이 ‘파손 없음’으로 검토하고 승인한 이미지로 한정합니다.
2. **승인 GT 우선.** 고정 운영점의 비교에서는 confidence 기준을 먼저 고정합니다. 같은 클래스이며 IoU ≥ 0.50인 쌍을 IoU 내림차순으로 일대일 매칭합니다. 동률은 GT 번호, 예측 번호 순서로 풉니다. 매칭된 쌍은 TP, 매칭되지 않은 승인 GT는 FN으로 남깁니다. 잘못된 클래스가 승인 GT와 IoU ≥ 0.50이면 클래스 혼동, 이미 매칭한 GT에 같은 클래스 예측이 중복되면 중복 FP로 기록합니다. 이 두 오류는 보류 구역과도 겹치더라도 유지합니다.
3. **남은 예측 처리.** 승인 GT 우선 처리를 마친 뒤, 남은 예측과 보류 영역 **합집합**의 교집합 면적을 예측 면적으로 나눕니다. 비율이 **0.50 이상**이면 ‘보류 영역 예측’으로 별도 집계하고 TP·FP에서 제외합니다. 0.50 미만이면 FP입니다. 경계선만 닿으면 교집합 면적은 0이고, 두 보류 박스가 겹치는 부분은 한 번만 셉니다. 매칭되지 않은 승인 GT의 FN은 이 단계에서 바꾸지 않습니다.
4. **집계 단위.** 프레임·클래스별 TP/FP/FN과 보류 예측 수, 제외 이미지 수를 함께 기록합니다. 후방 525·540·555는 동일 파손의 연속 관찰 가능성이 있고 Front와 Rear도 동일 주행·대상을 볼 수 있습니다. 실제 사례 단위 집계는 사용자가 프레임 간 대상 대응을 확인한 그룹에 한합니다. 모델 추론·성능 측정은 이번 단계에서 수행하지 않았습니다.
