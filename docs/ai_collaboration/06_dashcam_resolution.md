# 06. 입력 해상도와 실제 블랙박스 D20 탐지

## 문제와 결정

640에서 혼합 모델이 놓친 세 프레임의 D20 위치가 입력 해상도를 높이면 회복되는지 확인했습니다. 사용자는 가중치와 GT, 평가 기준을 고정하고 640·960·1280 전체 프레임을 비교하도록 지정했습니다. GT에는 앞 단계에서 사용자가 직접 검토·승인한 D20 5개와 정상 배경 3장이 포함됩니다. [사용자 승인 기록](04_manual_annotation.md) · [이전 640 비교](05_dashcam_model_roi_evaluation.md)

## 실제 원문과 수행 범위

첨부 원문과 보관본의 SHA-256은 `9c537dfc917e0efcbf92ca80103d51ccabc9fd0478f064de596da8fea0356e0c`입니다. 이 문서의 설명은 사후 요약이며 발송 전 수정 이력은 미확보입니다. 사용자는 실험 범위와 판단 우선순위를 정했고, Codex는 기존 추론·평가 모듈을 확장해 CUDA 실험과 보존 검사를 수행했습니다. [Part 5.4 원문](prompts/part5_4_dashcam_resolution.md)

## 검증과 남은 판단

각 해상도에서 모델과 predictor를 새로 준비하고 실제 forward 입력 형상과 FP32를 확인했습니다. 640 재현성 비교 중 메모리와 디스크의 좌표 표현 차이로 일치 판정이 잘못됐습니다. 저장 파일에서 좌표와 점수의 최대 차이가 모두 0임을 확인하고 비교 함수와 회귀 테스트를 보완했습니다.

코드 구현과 실험 검증은 완료했습니다. 0.05에서 두 고해상도 모두 기존 미탐 3개를 회복했고 1280은 640 대비 정상 배경 FP 수를 유지했습니다. MVP 후보는 1280 전체 프레임입니다. 이 표본은 이전 실험과 같으므로 독립 주행 성능은 미확정이며, 서비스 적용은 사용자 검토 대기입니다. [측정치·검증·다음 단계](../experiments/part5_dashcam_resolution_evaluation.md)
