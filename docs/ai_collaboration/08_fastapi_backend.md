# 08. 기존 MP4 분석을 로컬 API로 제공

## 문제와 역할

Part 5.5 전방 영상에서 D00 박스 195개가 34초 구간 하나로 묶였습니다. 사용자는 기존 모델·CLI를 유지하면서 웹에서만 최대 5초로 나누고, 업로드부터 상태·결과·영상·대표 이미지 조회까지 FastAPI로 연결하도록 요청했습니다. [이전 발견](07_mvp_video_pipeline.md) · [실제 요청 원문](prompts/part6_1_fastapi_backend.md)

사용자는 잠정 길이·API 경로·단일 사용자 범위·실제 검증 영상과 보호 대상을 지정했습니다. Codex는 코드·웹 의존성·테스트·문서와 CSV 비교·실제 CUDA HTTP 검증을 수행했습니다. 이 단계에서 사용자가 새 대표 장면을 직접 파손 판정하거나 React 화면을 검토한 근거는 없습니다.

원문 첨부와 보관본 SHA-256은 `fc780efa789744dfb8acb9180885c39229fc0f6cedb7d8b8be2d7a5d396b9954`로 같습니다. 이 사례 문서는 사후 요약이고 발송 전 편집 이력은 미확보입니다. 이번 요청 이후 별도 기능 변경 지시는 없었습니다.

## 결정과 수정

- 최대 구간 길이는 선택 옵션으로 추가하고 기존 CLI에서는 제한 없이 둡니다. 객체 식별을 새로 도입하지 않고 검토 단위만 나눕니다. 전방 9→16구간, 최대 34→5초, 후방 13구간 유지이며 전체 283박스가 정확히 한 번씩 보존됐습니다.
- 외부 큐·DB 없이 단일 Queue와 스레드, 파일 JSON 저장을 사용했습니다. OS 파일 잠금으로 같은 저장소의 이중 서버를 차단하고 재시작 때 미완료 작업을 failed/interrupted로 표시했습니다. 완료 처리 전에 실제 결과 파일을 검사합니다.
- 요청을 받은 스레드에서 업로드를 청크 저장하고 전체 디코딩을 검증한 뒤 202를 반환합니다. GPU 분석은 별도 워커가 실행합니다. 사용자 파일명·내부 경로를 API 파일 경로로 사용하지 않습니다.
- 초기 `.venv` 실행은 샌드박스의 원본 Python 경로 접근 제한으로 실패했습니다. 권한을 확장한 실행에서 기존 버전과 CUDA 연산을 확인했으며 인터프리터·AI 패키지를 교체하지 않았습니다.
- 첫 API 테스트에서 크기 제한의 PlainText 오류와 OpenAPI의 GET/HEAD ID 중복을 발견해 경로 단위 본문 제한·오류 정규화·HEAD 스키마 제외로 수정했습니다. 기존 httpx는 정상 실행돼 새 클라이언트 패키지로 교체하지 않았고 사용 중단 예정 경고를 한계로 기록했습니다.
- 최종 검토에서 종료 신호 뒤에 작업이 등록될 수 있는 경합과, UUID 충돌 때 기존 업로드를 정리할 수 있는 경로를 보완했습니다. 종료·등록에 같은 잠금을 적용하고 독점 생성에 성공한 디렉터리만 정리 대상으로 삼았습니다. 두 회귀 테스트를 추가한 최종 전체 테스트는 151개가 통과했습니다.

세부 수치와 검증 명령은 중복하지 않고 [Part 6.1 보고서](../experiments/part6_fastapi_backend.md)에 연결합니다. 웹 의존성은 [환경 문서](../ENVIRONMENT.md#part-61-웹-의존성-추가), React 연결 규칙은 [API Contract](../api_contract.md)에 기록했습니다.
