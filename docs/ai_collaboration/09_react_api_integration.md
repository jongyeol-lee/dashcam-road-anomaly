- 사용자는 Part 6.2-4 첨부 원문에서 기존 화면 디자인을 유지하고 실서비스를 기본 흐름으로 삼도록 지정했습니다. 원문은 대화 첨부에 있으며 SHA-256은 `baed08aeb52dc62cff7b663a68d431a6a0232565e1d2c906e17142533ba86df3`입니다.
- Codex는 실제 작업을 `/jobs`, 예시를 `/examples/jobs`에 연결했습니다. 상태 조회가 끝난 뒤 다음 조회를 예약하며 종료 상태나 페이지 이탈 시 조회를 멈춥니다. 장면 선택 동작에서만 영상 이동을 요청해 필터나 정렬을 바꿔도 재생 위치를 유지합니다. [API 계약](../api_contract.md)
- `Dashcam-Front.mp4`를 Edge 158에서 업로드했습니다. HTTP 202 이후 대기·분석 중·완료를 확인했습니다. RTX 3060 Ti의 `cuda:0`에서 FP32 입력 69장, 탐지 박스 234개, 의심 구간 16개를 확인했습니다. [분석 요약](../../outputs/video_analysis/jobs/39b6ea80-7e3e-441f-882e-8ff2c093e5b7/summary.json)
- Edge에서 목록과 상세의 JPEG 표시, MP4 Range 응답과 재생, 메타데이터 로딩 전 선택과 같은 장면 재선택, 타임라인 시점 이동을 확인했습니다. 실제 작업 URL 직접 접속과 새로고침도 확인했습니다.
- 오류를 유도해 상태·결과 조회와 MP4·JPEG 재시도를 검증했습니다. 실제 서버에 잘못된 MP4를 보내 HTTP 422 안내와 POST 1회를 확인했습니다. Windows의 영상 연결 종료 과정에서 백엔드에 `WinError 10054` 로그가 관찰됐습니다. 서버가 포트를 닫은 뒤에도 프로세스가 남아 검증용 프로세스를 종료했습니다.
- 기존 Python 경로는 샌드박스에서 접근이 제한돼 권한을 확장한 실행으로 FastAPI를 시작했습니다. 검증에는 기존 가상환경과 프로젝트 로컬 Node.js를 사용했습니다.
