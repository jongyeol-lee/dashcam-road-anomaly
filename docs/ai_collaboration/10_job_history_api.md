# 10. 분석 이력 데이터 및 API

2026-11-26 (KST) · 기준 커밋 `a26de59`

- **사용자 요청의 사후 요약.** 기존 작업과 사용자 검토를 보존하면서 파일 정보, 검색·필터·정렬·페이지네이션, 분석·검토 요약을 제공하는 읽기 전용 목록 API를 요청했다. 실제 완료 작업을 재사용하고 신규 실제 MP4 분석은 최소화하도록 지정했다. 원문은 대화 첨부에 있으며 SHA-256은 `6d8671b2e4171ef6eb95403e52c6eb5ae7bc5c179df873df3388467638e7ea78`이다. 발송 전 편집 이력은 미확보다.
- **Codex의 검증과 결정.** Before에서 기본 서버의 HTTP 405와 기존 작업의 파일 정보 미저장을 확인했다. 메타데이터를 작업 상태와 한 번에 저장하도록 기존 JSON을 확장했다. 목록에서는 상태 파일만 순회하고 페이지에 포함된 완료 작업의 결과·검토 파일을 읽는다. 검토 집계 오류는 null과 작업별 경고로 제공한다. [API 계약](../api_contract.md#분석-이력)
- **오류 해결.** 파일 정보 없이 등록한 작업에 null 키가 추가되면서 기존 종료 테스트가 실패했다. 기존 작업의 저장 키와 새 목록의 null 응답을 유지하도록 직렬화를 조정했다. Playwright에서는 종료 전 화면을 확인하지 않고 곧바로 뒤로 가는 기존 테스트의 순서를 바로잡았다.
- **실제 검증.** 기존 서버와 충돌하지 않도록 8014에서 완료 작업 7건의 사본을 조회했다. GPU로 전방 MP4 한 편을 추가 분석하고 파일 크기·검색·Range·JPEG를 확인했다. 기존 후방 작업의 오탐 2건을 개별 API·이력·Edge 결과 화면에서 대조하고, 재시작 뒤 목록과 원본·사본의 JSON 해시를 비교했다. [실험 보고서](../experiments/part6_job_history_api.md)
