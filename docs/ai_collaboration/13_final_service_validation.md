# 13. 최종 웹 서비스 검증과 중단 후 재개

**요청과 역할.** 사용자는 MVP 설정을 유지한 상태에서 신규 MP4의 실제 GPU 분석, 검토 영속성, 출력 정합성, 상세 URL 파일명 복원 및 이력 재접속을 요구했다. 기존 Part 6.4-3의 수정본을 직접 검토한 후 커밋·푸시했다는 내용은 사용자가 제공했다. Part 6.5 화면 조작, 저장 상태 선택, 테스트와 PDF 출력은 Codex가 실행했다. [최초 요청 원문](prompts/part6_5_final_service_validation.md)

**가설과 수정.** 파일명이 빠진 이유는 직접 주소에 Router 전달 상태가 없기 때문이었다. 먼저 상태를 한 번 더 조회해 이름을 가져왔지만 요청 수 회귀가 이를 잡았다. 결과 조회에 이미 사용한 메타데이터로 응답 필드를 추가해 해결했다. 이력 문제는 브라우저 뒤로 가기 전부터 발생했다. 검색 제출 직후 상태 핸들러가 이전 렌더의 조건으로 다음 주소를 만들었다. URL 전환 단계별 추적과 수정 전 실패하는 테스트를 남기고 이벤트 시점의 주소로 다음 조건을 계산했다. [검증 보고서](../experiments/part6_final_service_validation.md)

**작업 한도 중단과 재개.** 사용자가 Codex 사용 한도를 소진해 중단됐고 복구 후 이어서 진행하도록 요청했다. 이 문단은 후속 채팅 지시의 사후 요약이다. 발송 전 편집 이력은 미확보다. 11월 28일 재개 시 미커밋 구현 9개 파일과 최초 요청 보관본이 있었고, 최종 보고서와 증빙 색인은 아직 없었다. 사용자 요약에 나온 48개 이후의 49개 통과 로그, 실제 Chrome 이력 5회, 합성 Liner PDF 렌더, GPU 종료·재기동 후 저장값 대조까지 디스크에서 확인했다.

**재개 후 수행.** 기존 신규 영상 결과를 유지하고 마지막 작업 트리에서 전체 Python 182개와 Edge 49개, 이력 회귀 독립 5회, 타입 검사·린트·빌드를 실행했다. 원본 MP4와 가중치 해시, 기본 포트의 제공 코드를 확인하고 출력물·증빙·API 계약·Part 7 인수인계를 정리했다. [최종 증빙](../../outputs/evidence/part6_5_final_service_validation/evidence_notes.md)

**적용과 한계.** 구현과 격리 로컬 검증 완료. 기본 8000 서버에는 상세 파일명 변경이 아직 적용되지 않았다. 자동 승인 검토는 실제 블랙박스 리포트가 제3자 확장에 노출될 수 있어 Liner 실행을 차단했다. 확장 없는 실제 PDF와 독립 프로필의 합성 Liner PDF를 각각 검증했다. Part 6.5 사용자의 직접 확인, 공개용 영상 선별, 독립 모델 평가와 배포는 후속 상태다.
