## 1. 프로젝트 및 작업 목표

프로젝트: 자동차 블랙박스 기반 AI 도로환경 이상 탐지 시스템

프로젝트 경로:
`C:\Projects\dashcam-road-anomaly`

Part 5.3-1에서 Czech + Japan 혼합 YOLO11n 모델의 실내 오탐 5건을 ROI 후처리로 제거했습니다.

하지만 기존 영상에는 확인된 파손 Ground Truth가 없어 실제 파손 탐지 성능이나 ROI 적용에 따른 정탐 손실을 평가할 수 없었습니다.

사용자 검토가 끝나기 전까지 YOLO 정답 라벨을 확정하거나 모델 성능을 평가하지 마세요.

다운로드 출처는 프로젝트에서 확인 가능한 자료를 기준으로 기록하고, 라이선스가 확인되지 않은 내용은 확정적으로 작성하지 마세요.

## 3. 사용자가 발견한 균열 의심 구간

사용자가 영상을 직접 확인하고 아래 구간에서 균열로 보이는 장면을 발견했습니다.

| 영상 | 균열 의심 시간대 |
|---|---|
| Dashcam-Front.mp4 | 14~18초 |
| Dashcam-Rear.mp4 | 3~5초 |
| Dashcam-Rear.mp4 | 17~19초 |

**위 시간대는 확정된 Ground Truth가 아닌 사용자 관찰에 따른 후보 구간입니다.**

실제 균열인지, 보수 흔적이나 포장 이음매인지, D00·D10·D20 중 어떤 클래스인지 아직 확정되지 않았습니다.

모델 예측 결과를 정답으로 자동 채택하지 마세요.

## 4. 작업 A — 균열 후보 프레임 추출

위 세 구간을 중심으로 0.25초 간격의 프레임을 추출해주세요.

기존 프레임 추출 기능을 최대한 재사용하고 필요한 부분만 확장해주세요.

다음 정보를 기록합니다.

- 원본 영상 파일명
- 원본 프레임 번호
- FPS와 프레임 크기
- 원본 영상 기준 추정 시간
- OpenCV 디코더 타임스탬프(사용 가능한 경우)
- 추출 이미지 경로
- 후보 구간 ID
- 이미지 SHA-256

정확한 프레임 인덱스와 시각을 사용하며, 반올림으로 인한 동일 프레임 중복 추출을 방지해주세요.

원본 프레임의 해상도와 비율을 유지해주세요.

세 구간 외에도 균열이 없거나 차선·보수 흔적이 보이는 배경 검토 후보를 영상별로 소수 추출해주세요.

단, 모델이 탐지하지 않았다는 이유만으로 해당 이미지를 정상 이미지라고 확정하지 마세요.

## 5. 작업 B — 시각 검토 자료 생성

사용자가 이미지를 쉽게 확인할 수 있도록 다음 결과물을 생성해주세요.

1. 구간별 Contact Sheet
2. 원본 해상도의 개별 프레임
3. 원본 파일명·프레임 번호·타임스탬프 표시
4. 구간별 대표 프레임 목록
5. 검토용 CSV

Contact Sheet는 다음 세 개 구간을 구분하여 생성해주세요.

- Front 14~18초
- Rear 3~5초
- Rear 17~19초

전체 추출 프레임을 확인할 수 있도록 하되, 상세 검토는 각 구간에서 중복도가 낮은 대표 이미지를 우선할 수 있도록 구성해주세요.

최초 수동 상세 검토 목표는 균열 후보 약 10~20장과 배경 후보 5~10장입니다.

정확한 수량을 강제로 맞추기보다 실제 구도, 가시성 및 중복 정도에 따라 선정해주세요.

단, 같은 균열이 연속 프레임에 반복해서 나타나더라도 독립적인 파손 사례로 계산하지 마세요.

## 6. 작업 C — 수동 검토 매니페스트

권장 출력 경로:

`data/processed/dashcam_validation/part532_candidate_review/`

다음 파일을 생성해주세요.

```text
part532_candidate_review/
├── frames/
│   ├── front/
│   └── rear/
├── contact_sheets/
├── review_manifest.csv
├── frame_metadata.csv
└── extraction_summary.json
```

`review_manifest.csv`에는 최소한 다음 정보를 기록해주세요.

- 이미지 ID
- 원본 영상 이름
- 원본 프레임 번호
- 영상 타임스탬프
- 후보 구간
- 개별 이미지 경로
- 중복·유사 프레임 그룹 ID(확인 가능한 경우)
- 사용자 검토 상태
- 사용자 판정 클래스
- 사용자 메모

초기 사용자 검토 상태는 모두 `미검토`로 설정해주세요.

사용자가 선택할 수 있는 판정은 다음과 같습니다.

- 균열 확인
- 파손 없음
- 판단 보류
- 라벨링 제외

`균열 확인`의 경우에도 Bounding Box와 D00·D10·D20 클래스가 확인되기 전에는 최종 정답으로 취급하지 마세요.

CSV는 Windows Excel에서도 한글이 깨지지 않게 열 수 있도록 저장 방식을 고려해주세요.

## 7. 작업 D — ROI 관련 검토 자료

Part 5.3-1의 ROI B 설정을 읽고, 기존 설정을 변경하지 않은 상태에서 후보 프레임에 ROI 경계를 표시한 비교 이미지를 추가해주세요.

다음 항목을 확인할 수 있어야 합니다.

1. 균열 의심 영역이 ROI B 내부에 있는가?
2. 가까운 노면의 균열이 제외 영역과 겹치는가?
3. Front와 Rear에서 카메라 구도가 어떻게 다른가?
4. 화면 하단 40%를 제외하는 기준이 다른 영상에도 적절한가?

실제 ROI 설정은 기존 코드의 정의를 기준으로 사용해주세요.

아직 정답 Bounding Box가 없기 때문에 균열 보존률이나 Recall을 계산하지 마세요.

ROI는 시각 검토용으로만 표시하며, 원본 프레임은 수정하지 마세요.
