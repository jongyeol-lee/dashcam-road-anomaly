## 4. 작업 B — Ground Truth 확정 준비

사용자 라벨 초안을 검증한 후 최종 승인에 사용할 검토 매니페스트와 시각화 자료를 준비해주세요.

다음 원칙을 적용합니다.

### 확정 가능한 파손 후보

사용자가 작성한 D20 및 D40 후보를 검토합니다.

특히 rear_000120의 D40은 포트홀 가능성이 있는 후보이므로 사용자 추가 승인 없이 확정하지 마세요.

### 판단 보류 박스

판단 보류 박스는 정상 배경 또는 확정된 파손 클래스로 취급하지 않습니다.

최종 GT와 별도로 불확실 영역을 관리할 수 있는 구조를 준비해주세요.

향후 평가 시 해당 영역과 겹치는 모델 예측을 무조건 오탐으로 집계하지 않도록 평가 방법을 설계해주세요.

기존 평가 코드가 불확실 영역을 지원하지 않는다면 필요한 개선 사항을 기록하고, 이를 처리하기 전에는 해당 이미지의 전체 Precision이나 오탐 수를 확정하지 마세요.

### 이미지 전체 판단 보류

rear_000135는 평가 제외 예정입니다.

박스가 없다는 이유로 정상 이미지 또는 빈 GT 이미지로 처리하지 마세요.

### 연속 프레임 관리

rear_000525, rear_000540, rear_000555는 동일 주행 구간의 파손 사례일 가능성이 높습니다.

프레임별 라벨과 실제 파손 사례를 구분하고, 동일 대상으로 추정되는 프레임의 그룹 정보를 기록해주세요.

Front와 Rear 영상도 동일 주행에서 촬영된 영상일 가능성을 고려하며, 독립적인 주행 환경이나 파손 사례 수를 근거 없이 확정하지 마세요.

### 정상 배경 후보

기존에 추출한 배경 후보 8장은 아직 사용자 검토가 완료되지 않았습니다.

자동으로 정상 이미지로 확정하지 말고, 사용자가 검토해야 할 이미지 목록을 별도로 정리해주세요.

### 최종 승인

최신 초안 버전, 좌표, 클래스, 판단 보류 영역 및 평가 제외 목록을 사용자에게 보고해주세요.

사용자가 승인할 버전을 명시하기 전까지 최종 GT 발행 및 YOLO 정답 라벨 변환을 진행하지 마세요.

검증용 데이터는 모델 추가 학습에 사용하지 않습니다.

기존 AGENTS.md의 프로젝트 범위, 데이터·모델 개발, 개발환경, Git 관련 지침은 그대로 유지해주세요.

- 기술적으로 중요한 작업, 실험, 오류 해결 및 의사결정은 `docs/ai_collaboration/`에 기록한다.
- 문제 정의, 해결 가설, 프롬프트의 주요 요구사항과 제약조건, AI 수행 내용, 사용자 수행·판단 내용, 검증 결과와 한계를 구분한다.

- AI 협업 기록은 기술 검증과 개발 진행을 보조하는 용도로 유지하며, 단순 변경까지 과도하게 문서화하지 않는다.
- 인증정보, 환경 변수 및 불필요한 개인정보를 협업 기록에 포함하지 않는다.
