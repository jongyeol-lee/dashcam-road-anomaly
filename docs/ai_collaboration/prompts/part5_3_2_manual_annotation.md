\## 5. 작업 B — 수동 Bounding Box 라벨링 방법 준비\
\
사용자가 원본 이미지에서 직접 Bounding Box를 지정하고 클래스 후보를 선택할 수 있는 최소한의 방법을 마련해주세요.\
\
우선 프로젝트에 기존 라벨링 기능이 있는지 확인하고 재사용해주세요.\
\
기존 기능이 없다면 현재 설치된 Python 및 시각화 라이브러리로 구현 가능한 간단한 수동 라벨링 도구를 검토해주세요.\
\
요구사항은 다음과 같습니다.\
\
1\. 원본 1920×1080 좌표 기준으로 Bounding Box를 지정합니다.\
2\. 후보 클래스 D00, D10, D20, D40 또는 판단 보류를 선택할 수 있어야 합니다.\
3\. 한 이미지에 여러 개의 박스를 지정할 수 있어야 합니다.\
4\. 사용자가 지정한 박스를 미리보기로 확인할 수 있어야 합니다.\
5\. 이미지별 검토 상태와 메모를 저장합니다.\
6\. 잘못 지정한 박스를 수정하거나 취소할 수 있어야 합니다.\
7\. 원본 이미지와 기존 검토 CSV는 자동으로 덮어쓰지 않습니다.\
8\. 별도 설치가 필요한 대규모 어노테이션 시스템은 도입하지 않습니다.\
\
GUI 기능을 구현하는 경우 Windows 환경에서 실제 실행 가능한지 확인하고, GUI 지원 문제가 발생하면 좌표 CSV를 통한 수동 입력 및 미리보기 방식으로 대체해주세요.\
\
AI 모델의 예측 박스를 Ground Truth로 자동 채택하지 마세요.\
\
사용자가 최종 승인하기 전의 라벨은 별도 초안 파일로 저장해주세요.\
\
\## 6. 작업 C — ROI B 경계 비교\
\
Bounding Box 초안이 작성되면 해당 박스를 기준으로 다음 정보를 계산할 수 있게 준비해주세요.\
\
\- 박스 중심이 ROI B 내부인지\
\- 박스가 ROI B 경계와 교차하는지\
\- 박스 면적 중 ROI 제외 영역에 속하는 비율\
\- 원본 이미지와 ROI 적용 이미지 비교\
\
ROI B는 기존 \`src/road_anomaly/roi.py\`의 실제 구현을 확인해 사용해주세요.\
\
박스 일부가 ROI 밖에 있더라도 기존 필터가 중심점 판정이라면, 단순 교차만으로 해당 박스가 제거된다고 판단하지 마세요.\
\
이번 단계에서는 Ground Truth가 확정되지 않았으므로 실제 Recall 손실을 계산하지 않습니다.\
