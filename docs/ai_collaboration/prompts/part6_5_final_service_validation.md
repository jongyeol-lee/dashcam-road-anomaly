## 4. 전체 서비스 통합 검증

실제 MP4 업로드부터 출력 파일 생성까지 하나의 사용자 흐름으로 검증합니다.

기존 사용이 허용된 전·후방 테스트 영상 중 적어도 한 편을 새 작업으로 업로드하고 실제 CUDA 추론을 실행합니다.

기존 완료 작업의 조회만으로 신규 분석 통합 검증을 대체하지 않습니다.

### 4.1 업로드 및 실제 AI 분석

- 정상 MP4 업로드
- 파일명 및 파일 크기 표시
- 분석 대기 → 진행 → 완료 상태 전환
- 실제 RTX 3060 Ti CUDA 추론 확인
- 프레임 추출 및 분석 정보 확인
- 의심 장면 및 대표 JPEG 생성
- 분석 소요 시간 기록
- 완료 후 결과 화면 정상 이동

업로드 요청 시간, 서버 대기 시간, AI 분석 시간 및 전체 사용자 대기 시간을 가능한 범위에서 구분합니다.

실제 추론 성능을 관측하되 학습 모델의 탐지 정확도를 검증한 것으로 표현하지 않습니다. 기존 검증 영상을 재사용할 경우 독립 성능 평가 영상으로 간주하지 않습니다.

### 4.2 결과 화면

- 원본 영상 재생 및 탐색
- MP4 Range 응답
- 타임라인 및 장면 선택
- 영상 시각과 대표 장면 일치
- 이전·다음 장면 이동
- 탐지 클래스 및 검토 상태 필터
- 대표 JPEG 확대 및 오류 재시도
- 모바일 및 데스크톱 레이아웃

기존 장면 배치와 디자인은 문제가 없는 한 유지합니다.

### 4.3 사용자 검토 저장

네 가지 검토 상태를 확인합니다.

- 미검토
- 파손 의심
- 오탐
- 판단 보류

저장 후 새로고침, 페이지 이동 및 서버 재시작 이후에도 검토 결과가 유지되는지 확인합니다.

저장 실패한 값이 분석 이력이나 출력 파일에 반영되지 않는지도 확인합니다.

검증을 위한 검토값 변경은 신규 작업 또는 격리된 복제본에서 수행합니다. 기존 사용자의 검토 기록을 임의로 수정하지 않습니다.

### 4.4 분석 이력

- 메인 최근 분석 이력 5건
- 전체 분석 이력 조회
- 파일명 검색, 상태 필터, 정렬
- 페이지 이동 및 초기화
- 결과 화면 재접속
- 검토 집계 갱신
- 뒤로 가기 및 새로고침 시 검색 조건 복원

이전에 검색어 복원 문제가 간헐적으로 발생했으므로 해당 흐름을 반복 검증합니다.

페이지네이션을 위한 합성 작업과 실제 분석 작업은 구분합니다.

### 4.5 결과 내보내기

같은 신규 완료 작업과 동일한 저장 검토 상태를 기준으로 다음 결과를 비교합니다.

- 결과 화면
- 분석 이력
- CSV
- Excel(XLSX)
- PDF

CSV와 XLSX의 장면 수, 31개 컬럼 및 검토 상태를 확인합니다.

CSV의 UTC 원본 정밀도와 XLSX의 KST 날짜 및 Excel 정밀도 차이는 기존 계약을 유지합니다.

PDF는 실제 파일을 생성해 모든 대표 이미지, 검토 정보, 분석 한계 안내 및 마지막 페이지를 확인합니다.

기존 PDF 빈 페이지 문제가 재발하지 않는지 Liner 활성화 조건에서도 가능한 범위에서 회귀 검증합니다. 기존 증빙을 활용하고 사용자의 브라우저 프로필은 임의로 변경하지 않습니다.

## 5. 상세 URL 직접 접근 시 파일명 복원

이전에 보류했던 파일명 표시 문제를 개선합니다.

현재 신규 작업의 원본 파일명은 서버에 저장되지만 상태 및 결과 화면은 React Router의 전달 상태에 의존하고 있어 URL 직접 접근이나 새 탭에서 파일명이 표시되지 않을 수 있습니다.

다음 요구사항을 적용합니다.

- 신규 작업의 원본 파일명을 서버 데이터에서 복원
- 상태 화면과 결과 화면 모두 적용
- 직접 URL 접근, 새 탭, 새로고침 지원
- 분석 이력 및 리포트에서 이동하는 기존 흐름 유지
- 파일명 정보가 없는 레거시 작업은 기존 대체 문구 또는 미확인 표시
- 파일명 조회 실패가 영상 재생이나 결과 검토를 막지 않도록 처리
- Mock 예시 작업과 실제 작업 구분

기존 `StoredJob`, 개별 작업 API, 리포트 API 및 프론트엔드 요청 패턴을 확인한 후 호환성을 고려해 최소 변경 방식을 선택합니다.

기존 API의 필드를 제거하거나 의미를 변경하지 않습니다. 추가 응답 필드 또는 별도 경량 메타데이터 조회가 필요하다면 설계 이유를 기록합니다.

파일명 확인만을 위해 전체 분석 이력을 반복 조회하거나 불필요하게 무거운 리포트 요청을 수행하지 않습니다.
