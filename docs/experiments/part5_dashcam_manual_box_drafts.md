1. **원본에서 위치를 확인합니다.** 상단의 ‘노면 확대’와 ‘ROI B 표시’를 각각 켜거나 끌 수 있습니다. 전체 화면과 확대 화면 모두 원본 1920×1080 좌표로 입력합니다. 프레임 번호는 0부터 시작하고 표시 시간은 원본 프레임 번호를 30 fps로 나눈 초입니다.
2. **드래그한 뒤 클래스 후보를 선택하고 ‘박스 적용’을 누릅니다.** 필요하면 `x1, y1, x2, y2`를 직접 고칩니다. 적용된 박스는 목록에 추가되고 다음 드래그로 새 박스를 만들 수 있습니다. 한 프레임의 여러 대상은 각각 기록합니다.
3. **목록에서 박스를 선택해 확인합니다.** 클래스나 좌표를 바꾸거나 다시 드래그한 뒤 ‘박스 적용’을 누르면 해당 박스가 바뀝니다. ‘입력 취소’는 적용 전 입력을 지우며, ‘선택 삭제’는 목록에서 해당 박스를 뺍니다. ‘다시 열기’로 마지막 저장 버전을 복원할 수 있습니다.
4. **이미지 단위 상태와 메모를 입력하고 ‘초안 저장’을 누릅니다.** 상태는 `미검토`, `검토 중`, `판단 보류`, `초안 작성`입니다. 박스를 기록할 때는 검토 상태도 직접 선택합니다. 박스 없이 보류하거나 대상이 보이지 않는다는 메모만 남길 수도 있습니다. 빈 박스 목록만으로 정상 노면이 확정되지는 않습니다.
5. **‘저장된 원본 · ROI 비교 열기’로 박스 위치를 대조합니다.** 현재 버전의 왼쪽 원본과 오른쪽 ROI 음영에 같은 번호의 박스가 표시됩니다. `?`는 ‘판단 보류’ 클래스입니다. ‘다음’으로 이동하면 지정한 순서의 다음 프레임이 열립니다.

## 박스와 클래스 기준

- 원본에서 눈으로 추적할 수 있는 부분을 타이트하게 감쌉니다. ROI 바깥의 부분도 포함합니다. 떨어진 흔적을 한 덩어리로 볼 근거가 부족하면 분리하거나 보류하고, 경계가 흐린 쪽을 메모합니다.
- 진행 방향을 기준으로 종방향 선형 균열은 **D00**, 횡방향은 **D10**, 여러 방향의 선이 연결된 망상 균열은 **D20** 후보로 둡니다. **D40**은 포트홀 후보입니다. 어두운 색이나 보수 패치의 윤곽만 보이고 함몰 근거가 약하면 **판단 보류**를 선택할 수 있습니다. [프로젝트 클래스와 기존 수동 검토 사례](part5_multicountry_visual_review.md)
- 박스는 왼쪽 위를 원점으로 한 정수 픽셀 경계입니다. `0 ≤ x1 < x2 ≤ 1920`, `0 ≤ y1 < y2 ≤ 1080`이며 오른쪽·아래 끝은 포함하지 않습니다. 예를 들어 `x2 = 1920`이면 마지막 가로 픽셀 1919까지 포함합니다. 잘못된 입력은 박스 목록에 반영되지 않습니다.

## ROI B와 초안 파일

기존 B의 꼭짓점을 가져와 `NormalizedRoi.classify()`로 중심 포함 여부와 경계 접촉·교차를 계산합니다. 이 영상의 B는 프레임 상단부터 **y = 648px**까지이며 경계 위의 중심도 유지합니다. 제외 면적 비율은 박스 면적에서 ROI 다각형과 겹치는 면적을 뺀 뒤 전체 박스 면적으로 나눕니다. 예를 들어 위아래 경계가 600과 696인 박스는 절반이 제외 영역에 있지만 중심이 648이므로 필터를 통과합니다. 이 예시는 좌표 규칙을 설명하기 위한 가상 박스입니다. [기존 ROI 판정](../../src/road_anomaly/roi.py) · [B의 꼭짓점과 음영 구현](../../scripts/diagnose_video_roi.py)

각 저장 버전은 `annotation_drafts/labels/<이미지 ID>/<버전>/`에 `draft.json`과 `roi_comparison.jpg`를 함께 둡니다. JSON에 원본 경로(`part532_candidate_review/` 기준), SHA-256, 번호·시각·해상도, 주행·유사 프레임 그룹, 이미지 검토 상태·메모와 박스 목록을 기록합니다. 각 박스에는 `candidate_class`, `xyxy`, `roi_b.center_inside`, `touches_boundary`, `outside_area_fraction`이 있습니다. 제외 면적 값의 범위는 0~1입니다. ‘다시 열기’는 가장 높은 저장 버전을 읽습니다. 동시에 두 창에서 같은 버전을 편집하면 뒤에 저장하는 창에 최신 버전을 확인하라는 메시지가 표시됩니다. 사용자와 GPT가 같은 영상에서 연결된 선, 보수 자국, 유리 반사를 서로 구분하기 어렵다고 관찰해 이 검토를 시작했습니다. 자동화는 여섯 프레임의 사본과 확대본을 만들고 사람이 입력한 좌표를 검증·비교하는 역할을 맡았습니다. 확대 구역이나 사전 관찰 의견으로 사용자 박스 또는 클래스를 채우지 않았습니다. 이 단계에서 모델 추론·학습, YOLO 정답 변환, Recall 측정은 수행하지 않았습니다.

다음 단계에서는 사용자가 원본과 인접 프레임을 보며 각 초안의 대상 유무·클래스·경계를 확인하고, 같은 대상으로 판단한 프레임 ID와 보류 사유를 남깁니다. 사용자가 승인한 이미지별 버전과 대상 그룹을 지정하면 해당 버전만 별도 GT로 확정할 수 있습니다. 보류 항목은 승인 목록에서 제외합니다.

### Part 5.3-3 진단용 평가 기준

1. 전체 보류와 미검토·검토 중인 프레임은 정답·예측 집계 양쪽에서 제외합니다. ROI 비교에는 동일한 원본 좌표계와 승인 GT 집합을 씁니다. ROI가 제거한 승인 대상도 미탐을 계산할 때 분모에 남깁니다.
2. 고정한 confidence에서 같은 클래스이면서 IoU ≥ 0.50인 예측과 승인 GT를 IoU 내림차순으로 일대일 매칭합니다. 동률은 GT 번호, 예측 번호 순서입니다. 매칭은 TP, 매칭되지 않은 승인 GT는 FN입니다. 승인 대상에서 확인된 중복 예측·클래스 혼동은 따로 기록합니다.
3. 승인 GT 우선 처리를 마친 뒤 남은 예측은 보류 영역 **합집합과의 교집합 면적 / 예측 면적**을 계산합니다. 겹친 보류 면적은 한 번만 셉니다. 비율이 0.50 이상이면 보류 영역 예측으로 별도 집계하고 승인 GT의 FN은 유지합니다.
4. 확인된 정상 배경의 미매칭 예측은 FP로 셉니다. **파손 후보와 부분 보류 프레임에서는 전체 라벨의 완전성이 확인되지 않았으므로**, 앞 단계에서 분류되지 않은 미매칭 예측은 추가 시각 검토 목록에 넣습니다. 어느 영역에 걸쳤는지와 검토 대기 수를 보존하고, 이 예측을 확정 FP나 포괄적 Precision에 넣지 않습니다. 이 규칙은 프로젝트 진단 전용입니다. 표준 YOLO mAP와 별도 집계합니다.
5. 후방 525·540·555번의 #1은 동일 사례일 가능성이 있습니다. 후방 120·135번도 동일 후보일 수 있습니다. 주행 그룹은 전·후방 공통 `dashcam_validation_front_rear`이고 유사 구간은 각각 `rear_17_19`, `rear_03_05`, 전방 510번은 `front_14_18`입니다. 실제 사례 ID는 미확정입니다. 프레임별 결과와 사용자가 동일성을 확인한 사례별 결과를 구분합니다.

D40 승인 후보가 0개여서 D40 Recall과 포트홀 탐지 성공률은 산정할 수 없습니다. 두 영상에서 선정한 소수 프레임과 연속 관찰만 포함하므로 전체 도로환경의 일반화 성능을 추정할 수 없습니다. 이번 단계는 기준 점검까지이며 모델 추론·성능 측정·서비스 적용은 수행하지 않았습니다.
