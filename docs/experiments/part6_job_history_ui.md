# Part 6.4-2 최근 분석 이력 및 전체 이력

2026-11-27 (KST) · `main`과 `origin/main`은 기준 커밋 `7e485ca`에서 일치했고 작업 트리는 깨끗했다. 목록 API는 `dcb2ba8`에서 구현됐다.

## 구현

- 메인 업로드 영역 아래에 최신 5건을 표시한다. 파일명, 생성 시각, 상태, 의심 장면 수, 검토 진행 현황과 상세 링크를 제공한다. 이력 조회와 업로드는 서로 다른 상태를 사용한다. 공통 헤더는 **영상 분석**과 **분석 이력** 링크에 현재 페이지를 표시한다.
- `/history`는 파일명 부분 검색, 상태 필터, 생성 시각 정렬, 20건 단위 이전·다음 페이지, 조건 초기화, 새로고침을 제공한다. 제출한 검색어와 상태·정렬·페이지를 URL 쿼리로 유지한다. 조건을 변경하면 첫 페이지를 조회하고, 저장소 변화로 페이지가 줄어들면 유효한 마지막 페이지 주소로 교체한다.
- React와 TypeScript의 기존 요청·오류 처리에 목록 응답 검증을 추가했다. 검색에는 URLSearchParams를 사용한다. AbortController로 지난 조건의 요청과 화면을 떠날 때 남은 요청을 정리한다. 같은 조건에서 새로고침이 실패하면 이전 목록과 오류를 함께 표시한다.
- 작업 상태에 따라 기존 분석 상태 또는 결과 화면을 연다. 이력에서 이동할 때 파일명과 복귀 URL을 전달한다. 목록으로 돌아오면 저장된 검토를 다시 조회한다. 개별 작업 API의 응답에는 파일명 필드가 없어, 새 탭에서 상세 URL을 직접 열면 `원본 영상`으로 표시될 수 있다.
- 완료 작업은 의심 장면 수와 사용자 검토 집계를 표시한다. 판단 보류를 포함한 검토 수는 서버 응답을 사용한다. 정상 무탐지는 `의심 장면 0건`과 `0 / 0건`으로 표시하며 null 요약은 미확인으로 표시한다. 작업 ID를 펼쳐 파일명이 같거나 없는 작업을 구분할 수 있다. 작업 데이터, 분석 결과, 검토 데이터, 파일 크기 경고는 영향을 받는 정보와 함께 안내한다. [API 계약](../api_contract.md#분석-이력)

## 격리 FastAPI와 브라우저 검증

기본 포트에는 기존 Node(5173)와 Python(8000)이 실행 중이었다. 8000의 OpenAPI에는 `POST /api/jobs`가 있었고 이력 GET은 등록돼 있지 않았다. 이번 Vite는 `http://127.0.0.1:5187`, FastAPI는 `http://127.0.0.1:8018`에서 실행했다. Playwright 브라우저의 API 주소만 전환하고 FastAPI의 CORS에 5187을 허용했다. 기존 작업 7건의 JSON·업로드 MP4·대표 JPEG를 격리 저장소에 복제했다. 전방 작업 한 사본의 표시용 이름만 `검증용 Dashcam-Front.mp4`로 입력해 현행 메타데이터 흐름을 확인했다.
