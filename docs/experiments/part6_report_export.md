## 공통 데이터와 화면

- FastAPI의 `JobManager.report()`가 검토 저장과 같은 잠금 안에서 `job.json`, `results.json`, `reviews.json`을 읽고 식별자와 장면 수를 확인한다. 응답에는 저장된 작업 메타데이터, AI 분석 원본, 사용자 검토, 검토 집계와 스냅샷 시각이 들어간다. JSON과 CSV가 같은 읽기 경로를 사용하므로 기존 작업 조회 계약을 재정의할 필요가 없다.
- Python 표준 `csv`가 전체 장면을 한 장면당 한 행씩 UTF-8 BOM과 원본 수치로 기록한다. 텍스트 인용 및 수식으로 해석될 수 있는 파일명 접두사 처리를 적용했다. 화면에서 필터를 적용해도 출력 범위는 전체다. 무탐지 CSV는 헤더만 제공한다. [엔드포인트와 31개 열 계약](../api_contract.md#분석-리포트-내보내기)
- React의 `/jobs/{job_id}/report`는 조회 시점의 스냅샷과 기존 대표 JPEG를 사용한다. 이미지가 모두 준비된 뒤 `window.print()`를 호출하며 A4 인쇄 스타일은 서비스 메뉴와 조작 버튼을 숨긴다. 긴 파일명은 줄바꿈하고 카드 단위 페이지 분할을 적용한다. 이미지 실패 시 실패한 항목을 다시 요청한다. 브라우저 인쇄 대상에서 **PDF로 저장**을 선택해 저장할 수 있다.
- 검토 저장이 진행 중이면 결과 화면의 내보내기 버튼을 잠근다. 저장 실패 시 재시도할 수 있고, 내보내기는 서버에 마지막으로 저장된 값으로 진행한다. 검토 파일이 없는 기존 작업은 미검토로 집계한다. 손상된 분석·검토 데이터는 API 오류와 재시도로 처리하며, 갱신에 실패하면 이전 스냅샷의 인쇄도 중단한다.

Excel의 `분석 결과` 시트에는 네이비 헤더와 줄바꿈, 첫 행 고정, 전체 데이터 필터를 적용했다. 파일 너비 설정은 날짜 4개 열 30, `class_label` 18, `original_filename` 34, `event_id` 16, `review_label` 15, `job_id`·`model_sha256` 23, 주요 영상 시각·점수 16–18, 좌표와 기본 열 13이다. 값이 긴 식별자는 셀 선택 시 수식 입력줄에서 전체를 읽을 수 있다. 네 시각은 KST 실제 날짜 셀, 영상 시각·점수·프레임·좌표는 숫자 셀이다. 시각은 밀리초까지 표시하며 UTC 원본과 더 높은 정밀도는 CSV에서 사용할 수 있다.

Windows Excel 16.0에서 후방 XLSX를 읽기 전용으로 열어 장면 13행·31열, KST 날짜 4개 열의 전체 표시, 한글 클래스·검토 레이블, 헤더 고정·필터를 확인했다. 길이 216자의 합성 파일명도 값 전체를 유지했고 `HasFormula`는 false였다. 합성 무탐지 통합 문서는 서식이 있는 헤더 하나와 31열로 열렸다. 사용자 재출력 CSV와 새 CSV를 다시 읽어 `exported_at` 이외 모든 필드 값이 일치하는 것도 확인했다.

### PDF 원인과 인쇄 수정

사용자 재검토 당시 머리글을 끈 PDF 원본은 확보되지 않았다. 보관된 이전 사용자 PDF의 빈 마지막 쪽을 Before로 남기고 Chrome 158.0.8127.38의 독립 프로필에서 같은 후방 작업을 재현했다. 외부 네트워크를 차단하고 설치된 Liner 7.18.61만 로드하자 머리글·바닥글을 끄고도 본문 없는 쪽이 한 장 늘었다. 최초 비교에서 추가 쪽의 용지가 기본 Letter로 바뀐 것도 확인했다. A4를 명시한 반복에서도 같은 빈 쪽이 발생했다.

기존 인쇄 CSS는 `page: road-report`를 `<main>`에만 적용했다. 확장이 보고서 바깥에 요소를 추가하면 Chromium이 문서 끝에서 이름 없는 기본 페이지로 전환했다. Liner의 개별 컨테이너를 숨기는 실험으로는 마지막 쪽이 남았다. 인쇄 미디어에서 페이지 이름을 리포트의 문서 루트에 적용하면 모두 같은 페이지 형식을 사용한다. 여백 13mm, A4 세로, 레이아웃, 글자·이미지 크기와 카드 분할 규칙은 유지했다. [W3C 이름 있는 인쇄 페이지](https://www.w3.org/TR/css-page-3/#using-named-pages)

### 회귀와 적용 범위

Python 181개(기존 178개와 신규 3개), Playwright 46개(기존 43개와 신규 3개), TypeScript, Oxlint, 프로덕션 빌드를 통과했다. 대표 전·후방 작업의 복제본으로 격리 FastAPI 8019와 Vite 미리보기 5189에서 브라우저 다운로드를 확인했다. 원본 작업 JSON, 대표 JPEG와 MP4는 SHA-256으로 전후 동일함을 확인했으며 재추론은 실행하지 않았다. 디버깅용 Liner는 독립 프로필에서만 로드했다.

기본 포트 8000의 실행 중인 서버는 XLSX 경로가 없는 이전 코드였고, 기본 Vite 5173은 수정된 프론트엔드를 제공했다. 기존 서버의 실행 상태는 그대로 두었다. 이후 사용자가 기본 백엔드를 정상 종료·재기동하고, 같은 브라우저 프로필에서 해당 후방 작업의 Excel 다운로드와 A4·머리글 해제 PDF 마지막 쪽을 확인하면 된다. 로그인된 Liner의 로켓 UI를 포함한 원래 프로필에서 보완 버전의 사용자 직접 검증은 남아 있다.
