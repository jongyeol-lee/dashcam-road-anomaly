# Part 6.3-2B-2 사용자 검토 결과 저장

2026-11-26 KST · `main` · 기준 `7a92244` · 시작 시 `origin/main`과 동기화, 로컬 변경 없음

기존 결과 화면에서 후방 영상 `event_0001`을 파손 의심으로 지정하면 집계가 1/13이 됐지만 새로고침하면 미검토와 0/13으로 돌아왔다. 기존 완료 작업의 복제본으로 이 현상을 재현한 뒤 검토 데이터 저장을 구현했다. [전후 증빙](../../outputs/evidence/part6_3_2b_2_review_persistence/evidence_notes.md)

## 구현

| 변경 영역 | 동작 |
| --- | --- |
| FastAPI `jobs.py`, `schemas.py`, `main.py` | 완료 결과의 작업 UUID와 실제 장면 ID를 확인한다. 기존 단일 워커와 잠금으로 `reviews.json`의 읽기·변경·원자적 교체를 묶는다. GET은 저장된 항목을 반환하고 PUT은 장면 한 건을 저장한다. |
| React `api/`, `useJobReviews.ts`, `ResultsPage.tsx` | 분석 결과와 검토 데이터를 따로 조회한다. 로딩·오류 동안 검토 상태는 미확인으로 두고 영상과 분석 결과를 제공한다. 같은 장면의 저장이 처리 중일 때 해당 입력을 잠그며, 저장 성공 응답으로 집계·필터를 갱신한다. |
| React `SceneDetail.tsx`, `helpers.ts`, `index.css` | 저장 중·완료·실패와 실패한 선택값을 표시한다. 실제 작업과 예시 모두 네 상태를 필터링하고 전체 검토 집계를 볼 수 있다. 목록·타임라인·이전/다음은 표시된 장면을 공유한다. |

작업별 JSON을 사용하면 기존 파일 저장소, 프로세스 잠금, 파일 교체 함수를 그대로 재사용할 수 있다. `reviews.json`에는 `job_id`와 `reviews` 배열을 두고 각 항목에 `event_id`, `review`, UTC `updated_at`을 저장한다. 이전 작업은 첫 저장 전까지 빈 배열을 응답한다. 미검토로 되돌린 장면도 마지막 수정 시각은 유지한다. 같은 장면의 동시 요청은 마지막으로 저장에 성공한 값이 남고, 서로 다른 장면의 값은 병합해 보존한다. 사용자 검토는 이후 조회할 수 있는 독립 데이터이며 모델 평가용 정답 라벨과 구별한다. [API 계약](../api_contract.md#사용자-검토-결과)

React 결과 화면 내부에서 다른 페이지로 이동해도 시작한 PUT은 계속 진행한다. 같은 작업에 다시 들어오면 진행 중인 PUT이 끝난 뒤 검토 데이터를 읽는다. 저장 실패 시 마지막으로 확인된 저장값을 유지하고 실패한 선택값을 보여준다. 탭을 닫거나 응답이 수신되기 전에 연결이 끊겼을 때는 다음 조회에서 서버에 실제로 저장된 값을 확인한다. 열린 다른 탭의 변경은 재접속 또는 새로고침 시 조회한다.
