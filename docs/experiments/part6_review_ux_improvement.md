## 개선 방식

후방 영상 결과에서 가까운 시각의 마커 버튼이 겹쳤다. 목록에서 마지막 장면을 선택하면 390×844 화면의 대표 이미지가 화면 위로 벗어났다. 데스크톱 타임라인에서 선택한 장면이 목록의 스크롤 영역 밖에 남았고, 작은 탐지 박스를 자세히 보려면 브라우저 배율을 조절해야 했다. 수정 전에 이 세 조건과 기존 업로드 화면을 캡처했다. [Before/After 증빙](../../outputs/evidence/part6_3_2b_1_review_ux/evidence_notes.md) · [기존 통합 검증](part6_service_integration_validation.md)

| 변경 파일 | 구현과 선택 이유 |
| --- | --- |
| `features/results/Timeline.tsx`, `helpers.ts` | `ResizeObserver`로 트랙 너비를 읽고, 38px 버튼과 4px 사이 간격을 기준으로 가까운 마커를 그룹화한다. 마커를 여는 동안에는 재생 시점을 유지한다. 그룹 안의 버튼에는 대표 시각, 탐지 종류와 장면 ID를 보여준다. 동일 시각과 동일 클래스도 각각 선택할 수 있다. 시간은 필요할 때 밀리초까지 표시한다. |
| `pages/ResultsPage.tsx`, `features/results/SceneDetail.tsx` | 장면 목록, 타임라인, 이전·다음이 같은 선택 함수로 연결된다. 이전·다음과 현재 위치는 필터·정렬 이후의 목록을 기준으로 계산한다. 데스크톱은 잘린 장면이 보일 만큼만 목록을 스크롤한다. 1023px 이하에서는 목록이나 타임라인에서 명시적으로 장면을 선택할 때 상세 제목을 보여주고, `목록으로`는 선택 항목으로 돌아간다. |
| `features/results/SceneImage.tsx`, `index.css` | 기존 JPEG를 비율에 맞춰 표시하거나 원본 픽셀 크기로 열 수 있다. 기본 HTML 대화상자가 배경 조작을 차단하며, 닫기·ESC·포커스 복원과 실패 후 재시도를 제공한다. 원본 크기에서는 이미지 영역에서 가로·세로로 이동할 수 있다. |

시간 간격을 고정하면 뷰포트에 따라 같은 두 버튼이 겹칠 수 있다. 마커를 여러 줄로 놓는 방법은 밀집 구간의 세로 공간을 더 차지하고 같은 시각의 버튼 배치에도 별도 규칙이 필요하다. 실제 트랙 너비를 기준으로 그룹화하고 한 줄을 유지했다. 가까운 마커가 연속되면 한 그룹에 여러 장면이 포함되므로 그룹 내부에 스크롤을 둔다. 데스크톱 목록에서 표준 `scrollIntoView()`를 쓰면 상위 페이지가 함께 움직일 수 있어 목록 컨테이너의 스크롤 위치만 계산했다. 모바일에서는 상세 확인까지 조작을 한 번 줄이기 위해 명시적 선택 시 이동하는 방식을 적용했다.

## 실제 브라우저 측정

Windows 11, 로컬 Node.js 26.13.1, Edge 158.0.4370.33, Chrome 158.0.8127.38에서 검증했다. 재분석 없이 기존 완료 작업을 사용했다. 같은 후방 작업의 날짜와 조건, 촬영 장면, 원시 로그는 증빙 목록에 기록했다. [실행과 캡처 조건](../../outputs/evidence/part6_3_2b_1_review_ux/evidence_notes.md)

- 마지막 장면 `event_0013`을 타임라인에서 선택했을 때 1440×1024에서 After 목록 스크롤이 0 → 752px 변했다. 해당 조작 동안 페이지 스크롤은 766px로 유지됐다. Before에서는 페이지가 707px에 머물렀고 목록도 0px에 그대로 있었다. 두 화면 모두 타임라인 상단에 맞춘 뒤 측정했으며 화면 구성에 따라 페이지의 절대 Y 위치는 달랐다.
- 390×844에서 목록의 같은 마지막 장면을 터치했다. 상세 제목은 뷰포트 기준 −1692px에서 32px로 들어왔다. `목록으로`를 누르면 해당 행이 다시 보이고 포커스를 받았다. 모바일 타임라인의 그룹에서 별도 장면을 선택한 뒤 확대와 닫기도 확인했다.
- Edge에서 실제 대표 JPEG의 화면 맞춤, ESC, 포커스 복원과 원본 크기 1920×1080 CSS px를 확인했다. Chrome에서 전방 2초 및 후방 4.5초 장면 선택, 정지 위치 보존, 재생 중 확대·닫기 후 재생 지속을 확인했다. 두 작업에서 MP4 Range 요청은 HTTP 206이었다. [최종 실측 로그](../../outputs/evidence/part6_3_2b_1_review_ux/2026-11-26T06-05-20-306Z_after/observations.jsonl)
- 사용 문서의 `python.exe -B -X utf8 -m src.road_anomaly.api`로도 헬스 응답을 확인했다. Windows Ctrl+Break 뒤 종료 로그가 기록됐으며 포트와 프로세스가 닫혔다. 기존 작업 상태 파일은 실행 전후 일치했다. [CLI 검증](../../outputs/evidence/part6_3_2b_1_review_ux/cli_ctrl_break_20261126T060620449636Z.json)

자동화에서 동일 시각·동일 클래스 분리, 키보드 그룹 선택, 확대 오류와 재시도, 배경 스크롤 차단, 첫·마지막 장면 경계, 필터와 정렬 시 시점 보존, 메타데이터 로딩 전 마지막 요청, 같은 장면 재선택, 무탐지·필터 결과 없음·길이 미확인, 모바일 터치 동선을 확인했다. 처음 실행에서 필터 초기화가 정렬도 초기화한다고 가정한 테스트를 수정했다. 기존 구현은 정렬을 유지하므로 재시험에서는 점수순 위치와 재생 시점을 함께 확인했다. 실제 브라우저 스크립트의 이미지 조회도 확대본과 미리보기를 구별하도록 수정했다.
